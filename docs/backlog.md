## Labels and status workflow

Keep exactly one label from each group: `type:*` (governance/architecture/feature/platform/testing/security/documentation), `priority:p0/p1/p2`, `phase:m0` through `phase:m8`, and `status:todo/in-progress/in-review/blocked/done`. Existing labels and milestones are retained. P0 is foundational, P1 core delivery, P2 later work; later does not mean optional for full coverage.

Open todo until work starts; change to in-progress with an issue-linked plan; use blocked with the actual blocker; use in-review when evidence exists. Close as completed with done only after all current criteria and completion dependencies are verified. Unfinished tests/demos stay unchecked. Reopening needs evidence that completion was invalidated, not merely a scope wording edit. Record commands/results, commits/PRs, decisions and limitations in the issue. Never invent passing checks or grading points.
